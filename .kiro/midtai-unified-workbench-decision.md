# Midtai Unified Workbench — 产品决议

> 状态：**已拍板**
> 本文档是后续所有工程任务的产品依据。评审过程见 `midtai-unified-workbench-implementation-brief.md`。

---

## 一、Midtai 是什么

**Midtai = 统一工作台。**

统一的范围：
- 壳层导航（顶部 tab、当前作品上下文芯片）
- 跨 tab 的"当前作品"上下文共享
- 作品库入口（统一入口，内部分设计作品库 / 图片素材库）

不统一的范围：
- 两个 tab 的主对象不同，不强行对齐
- 两个 tab 的左侧布局、交互模式不需要对称

---

## 二、三个核心概念的定义

### 作品（Work / Project）

- 用户有意识创建、保存、可迭代的设计输出
- 有版本历史、有画布、可以继续改
- **只有用户真正生成第一版后才存在**
- 对应数据模型：`designProject` + `designVersion`
- 设计 tab 的主对象

### 素材（Asset / Material）

- 图像 tab 生成的图片结果
- 可供多个作品复用，本身不是作品
- 可以"插入当前设计"，从素材升级为某个作品的组成部分
- 对应数据模型：`imageGalleryStore` 里的图像记录
- 图像 tab 的主对象

### 会话（Session）

- **会话是实现细节，不是产品概念。**
- 会话是作品的属性（design session 隶属于某个作品），不是和作品平级的一等公民
- 用户不应该通过"会话"来管理设计工作流
- 主 chat 侧边栏不再是设计工作流的管理入口（短期可保留实现，但不再强化，长期要下沉）

## 三、四条产品规则

### 规则 1：统一壳层，不统一主对象

图像 tab 主对象是**素材**，设计 tab 主对象是**作品**。  
这个不对称是合理的，不要强行对齐。

### 规则 2：新建作品 = 进入临时工作态，不立刻入库

点击「新建作品」后发生的事：

1. 进入一个**临时工作态**（Transient Work State）
2. 右侧 design chat 清空，显示空态提示（"描述你想要的设计"）
3. 左侧 UI 可以显示"新作品·未命名"条目，样式区分（暗显 / 虚线）
4. 该状态持有：当前 prompt 草稿、临时 designFlowState、session transcript
5. **但它不是正式 project**：不进作品库，不进作品列表，不产生 `designProject` 记录

**入库触发点（唯一）：**
用户真正生成第一版 artifact → 触发 `saveDesignArtifactToProject()` → 作品正式存在。

**关键区分：**
- "不入作品库" ≠ "不允许临时工作态存在"
- 临时工作态可以有 session、有 transcript、有 designFlowState
- 只是这些数据在用户生成之前不对外暴露为正式作品

### 规则 3：同一个 design chat 默认只服务一个作品

**分流触发条件：当前作品已生成过至少一个版本，用户又发了新 brief。**

不做意图识别，直接弹分流框：

```
你想怎么继续？
  ┌─────────────────────────────┐
  │ [继续当前作品]               │
  │ [新建作品]                  │
  │ [基于当前作品另起一版]        │
  └─────────────────────────────┘
```

未触发条件（不弹框）：
- 当前作品尚未生成过任何版本（处于临时工作态）→ 直接继续，不打断用户

### 规则 4：主 chat 侧边栏不再承担设计工作流管理职责

- 产品方向上明确：设计工作流的管理入口在 Midtai 设计 tab 内部
- 短期实现可以保留（`sessionType: 'design'` 条目仍然出现在侧边栏）
- 但不要继续强化侧边栏作为设计工作流主入口的设计
- 长期目标：design session 下沉为作品的属性，侧边栏只承载普通 chat session

## 四、正式入库的唯一条件

```
触发：用户点「进入画布」（design chat 内）或「进入 KainClaw Design」（主 chat artifact panel）
条件：artifact 已生成，用户主动触发
行为：saveDesignArtifactToProject()
        → 创建 designProject（source: 'artifact'）
        → 创建 designVersion v1
        → 写入 chat message.designProjectId
        → 左侧临时条目升级为正式作品条目
```

任何其他时机（点新建作品、发 brief、生成中）都不触发入库。

## 五、两个 tab 的主区域布局规则

### 图像 tab

- 左侧：工具区（prompt、参数、操作按钮）+ 当前目标上下文芯片
- 右侧主区，从上到下依次：
  1. 当前批次生成中（skeleton 状态，生成完成后消失）
  2. 本轮最新结果（可直接操作：插入当前设计 / 做变体）
  3. 历史图片网格（长期积累，不和当前批次混排）

### 设计 tab

- 左侧：最近设计作品列表（5~8 个）+ 「新建作品」按钮
  - 完整历史统一进作品库，不全量放左侧
- 右侧主区：当前作品的三个子视图（tab 切换）：
  1. 设计对话（design chat）
  2. 画布预览
  3. 版本记录

### 作品库（顶部独立 tab）

- 设计作品库（`designProject` 列表，只含已正式生成的作品）
- 图片素材库（`imageGalleryStore` 列表）

## 六、工程分阶段

### Phase 1（可现在启动，纯 renderer 层）

- 设计 tab 左侧加最近作品列表（复用 `designProjectStore`）
- 图像 tab 右侧拆成三区（生成中 / 本轮结果 / 历史网格）
- 顶部加「作品库」入口
- 「新建作品」进入空白 design chat（不写 store）

### Phase 2（等 c68 + pul 验收稳定后）

- 作品库统一页（设计作品库 + 图片素材库）
- 左侧临时条目与正式作品条目的 UI 状态区分
- 分流弹框（触发条件：当前作品已有版本，用户再次发 brief）

### Phase 3（单独架构设计后排期）

- Design chat 和作品真正绑定（1 chat : 1 project）
- `conversationHistory` 从 session 迁移到 project 层
- 主 chat 侧边栏的 design session 条目下沉或移除
